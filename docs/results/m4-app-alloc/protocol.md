# Linux application allocation measurement protocol

Freeze the baseline at 069e56f915a4f94b7c7b824446c05df1c85889fb before product edits. Repeat the same standard trials on the combined core and application candidate. Store observations from each invocation in a fresh utcp-data directory. Report source and binary SHA, kernel, argv, pinning and tool controls.

Use a glibc-specific process counter, enabled only in the userspace endpoint. Count successful allocation requests and requested bytes. Report C family and throwing/nothrow scalar/array/aligned C++ new with nested C malloc counted once. Exercise zero-size, C, C++, realloc and aligned controls. Exclude the observer via separate processes and fixed storage. Distinguish initialization, live traffic and shutdown. Attribute hot caller groups using symbolized return addresses in a separate diagnostic arm as needed. Report remaining costs even when they cannot be eliminated. Report mapping-backed growth separately if present.

Exercise bidirectional roles with a native kernel peer, regular JSON/statistics sampling enabled for bulk, byte pattern and peer hash agreement. Bound counts against same-clock bracketing segment/byte samples. For staged/direct echo, check regular server/client reports, successful byte-verified requests and traffic inside the measured interval. Report cold costs, warm-up, steady-state, growth and shutdown independently where observable. Do not infer a positive branch from a flag. For TCPv4 and multiqueue inspect actual counter or fd evidence, including fallback, backpressure and both queues. Report unobserved branches.

For recorder-enabled runs, keep the production 64 MiB first block, retain every event in memory to shutdown, inspect a real block boundary, validate in-order formatted events, preserve periodic reporting and capture RSS/HWM. Separate capture from shutdown formatting and count its allocations. Count-only is independently covered by the core team. These tests do not estimate throughput changes. No M3 reruns.
