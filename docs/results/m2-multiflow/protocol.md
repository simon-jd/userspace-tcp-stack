# M2d multi-flow acquisition conventions

Coordination draft frozen before any multi-flow traffic. Actual implementation belongs to the later task. Reference source is commit `4f9c9b89e16188fd65f3961af967cc3d83370d12`; the design is M2 §§5.6–5.7, 5.9–5.13 and 6. The CSV is a schedule, not measured data or input to the current single-flow CLI.

## Run order and identities

The CSV contains one row per matched pair. Expand each row to its two consecutive sides in the listed order on the same granted slot. Simulation, setup, controls, gates, failed or interrupted attempts do not replace the 100 planned scenario runs. Both sides share the listed pair seed, ports, durations and join roles. Scenario 9 alone uses 10 Mbit/s, 100 ms and 120 s. All others use 100 Mbit/s, 20 ms and 60 s. All use zero configured loss and 2×BDP. Distinct flow IDs are fixed across repetitions, including #7's two CUBIC senders and #10's four participants.

For reproduction let H(tag,s,r) be the SHA-256 hex digest of ASCII `2026111906/tag/s/r` with unpadded decimal numbers. Sort the 50 pairs by H(order,s,r). For each scenario rank its five repetitions by H(side,s,r); the first three in odd scenarios and first two in even scenarios run the test side first. The shared netem seed is 1 plus the unsigned integer of H(netem,s,r)'s first eight hexadecimal digits modulo 2147483647. Archive the schedule actually consumed and record physical attempt order including interruptions. Retain partial pairs and rerun the entire pair back to back with the original order and seed; follow RESULTS.md's registered rerun cap and flag rules.

## Reusable machinery and required additions

- `testbed/m2/{common,up,shape,record}.sh` provide four containers, 8 routed TUNs and a single r1-forward netem/r2-forward TBF. With zero-based flow index k and slot N, use stack `--tun utcpK --addr 198.18.(8N+k).2`, kernel peer .1/24, and unique TCP receiver ports 5201+k on each side. All flows share snd's eth0, qdiscs and receiver. Linux's active connect has no source bind CLI. Its source is selected by routing and its port is ephemeral. `--addr` sets the stack address. On the kernel backend `--cc newreno` selects Linux reno. Take actual 4-tuples and CC names from the captures and per-flow sender samples. Do not require distinct ephemeral port numbers across distinct tuples.
- `record.sh` records every interface's link, pfifo, routing and counters but does not associate PIDs with TUNs. Validate its pre/post data for every assigned TUN and corroborate actual use with process arguments, per-TUN traffic deltas and both captures' source-IP/destination-port mappings. Namespace totals in mixed groups remain scenario totals. Run one Linux listener per flow, wait for all unique listener sockets, then use a common in-container release barrier for incumbents and an absolute monotonic deadline for the join. The existing proof barrier synchronizes independent one_run calls across slots; concurrent one_run calls on one slot would clean up one another's endpoints, qdiscs and captures. Detached listeners provide no recorded exit code today; collect each exit and both final summaries.
- One pre/post snapshot, one shaping operation and TCP metrics flush, one r1-in/r2-out capture pair, one sampler and one `ping -D -O -i 0.05 -s 56` from sender kernel to receiver per scenario. Start captures and collect three idle ping seconds before the first connect. Preserve requests matched to replies by ICMP ID and sequence, missing replies, clock pairs and ping.txt. Convert capture CLOCK_REALTIME to CLOCK_MONOTONIC. Report base from idle replies, window losses and delay with source. Ping characterizes the shared path. It cannot distinguish individual flows.
- Slot 0 uses sender/ping CPUs 8,9, receiver 10 and both routers/capture 11; keep slot 1 down for production. All app instances share their role's cpuset. Record IRQ/softirq, softnet, foreign CPU and per-flow lateness, including the eight-flow case against comparable one-flow CUBIC. Analyze, plot and build on E-cores 16–31 at nice 10. No campaign overlap.

## Clocks, metrics and report

Use bulk's receiver JSONL `start` (accept) and sender JSONL `start` (connect). Register t0 as earliest incumbent accept and join as the late flow's accept. Schedule incumbents for 0 s and the designated last flow for 20 s; give them nominal write durations S and S−20 respectively. Record actual release, connect and accept offsets, initial spread, and join error rather than treating a shell launch as an accept. Check observed order and timing in both sides. Bulk's write timer starts at sender connect; drain is outside active measurement. Preserve nominal end t0+S and every sender's start+duration. The design specifies the former for Jain; existing RESULTS.md caps a single flow at sender write-stop. Before traffic, resolve this explicitly in the acquisition brief: report nominal Jain as defined with bracketed receiver samples and also show active-overlap Jain to E=min(t0+S, every sender's start+duration). Label any drain difference and use the observed active endpoint for the convergence check. Never extrapolate a missing boundary. Clock ordering, sampling coverage and timing tolerances should be checked by a non-counted rehearsal and frozen before production.

- Interpolate each receiver's cumulative bytes at the window bounds. Report per-flow post-warm-up goodput from its own accept+5 to common active end E; keep per-flow Jain-window rates separately. Jain = (Σx)²/(nΣx²), with x in the same [actual join+20, nominal end] window for every participant. Use matching Linux roles for gap verdicts. C is the actual item-2 Linux CUBIC calibration goodput for the same slot, key, bandwidth, RTT and 2× queue. Record source path and digest for each C. Reuse analyze.py's convergence_time, which starts at join+1 s, checks 1 s means every 100 ms and requires all flows within ±20% of C/n for 5 uninterrupted seconds. Distinguish failure to converge, invalid input and missing measurement. Show the converged count out of five; carry non-converged runs as censored at their measured horizon and label any conditional numeric ranges.
- Compare five matched-role goodputs by median/min/max. A gap requires >10% of the Linux median and disjoint closed ranges. Report |ΔJain|>0.05 and convergence separately. Retain adverse values, inspect causes of gaps and keep both versions after a fix. Plot proposal for otherwise ambiguous “median repetition”: for each side select the median summed per-flow goodput over the common fairness window among five counted repetitions, tie by repetition ID. Plot every flow in that real run on the same time origin, include the delayed join and label both repetition IDs. Record this convention before outcomes.
- Use one scenario directory and per-flow sender/receiver JSONL, stdout, stats and traces for stack flows, measured sender and receiver CC/backend when available, bytes and SHA-256. Retain common `meta.json`, shape, pre/post records, ping, TBF samples, tcpdump logs, captures, summaries and schedule, plus attempted run/flow IDs. Validate per-flow positive matching bytes/SHA, role/backend/CC, sample coverage and rates. Reuse capture_summary's dport filtering or demultiplex once. The ordinary summarize_run, fixed ARCHIVE_FILES and tables/plot commands assume a single pair of endpoint files. Adapt in owned files. Check compact restore reproduces CSVs and plotted repetition choices and the raw restore reproduces both nonempty pcaps, sizes and counts per physical attempt. Record all flags and separate incomplete/not-converged results from measured zero.

## Acquisition boundary

1. Current activity is static reading plus plan generation off-host only. Isolated offline work later can replay existing artifacts read-only or fixtures to verify clocks, flow identity, gap thresholds and censoring. Label fixture results as validation. No rerun or matrix data changes follow from this preflight.
2. After matrix acceptance and slot release, branch from its accepted main; implement in owned multiflow files and its results section. Validate distinct listeners/TUNs, stagger, interrupted pairs, nested archives and evidence on non-timing resources. Test missing, duplicated or swapped flows, early exit, absent echo, and non-convergence. No change to record.sh is necessary to check its output. Coordinate separately if a change outside task ownership becomes necessary.
3. matrix.py tree_hash reads every regular file below testbed/m2 and tools/m2, including untracked files, except __pycache__. The key also binds bulk/core hashes, preset, kernel, image, recorded sysctls and module parameters. A new multiflow*.sh, multiflow.py or plan there changes the key even with unchanged binaries. Keep historical matrix and gate evidence under their exact original key. Freeze the actual new runtime, run complete gates on the authorized timing slots (items 1–6; 67 criteria per complete slot), and re-open source-bound gate evidence through check_gate before production. Keep serial mode; a passing simultaneous proof cannot supersede the prior serial decision. If citing a same-key 15-transfer proof, obtain one on the final key. Use its five qualifying serial one-flow CUBIC records as lateness controls when available, otherwise collect matching serial controls and label duration/conditions. No historical control should be relabelled as a new-key run. Review and verify the frozen runner, campaign/archive and all-preset CI per the normal task process.
