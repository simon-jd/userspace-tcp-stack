# M3 defensive Gen6 normal session sweep

The `gen6-normal-v1` profile uses Gen6 seeds 0 through 999,999 with two real Stack peers and one bidirectional TCP session per seed. The sweep uses the Release build with UTCP_DCHECK and strict fast retransmit checks. The session sends the generated byte patterns in both directions, uses write shutdown and reads to EOF. The generator retains the seeded congestion control, receive buffers, path rates, queues, ordinary loss and bursts, jitter, reordering and duplication. Both links have a 1,500-byte MTU. Full stream, termination, progress, in-flight, pacing and quiescence checking remains active.

At the base revision, `generate_scenario` returns through the congestion generator for version 6. That path uses the default values of zero for `icmp_spoof_ppm`, `garbage_ppm` and `bitflip_ppm`, so forged controls, mutation, garbage replay and bit flips are absent. The version 3 generator contains the variable MTU and additional close modes. The normal profile uses the existing Gen6 topology and session, and clears the shared node generator's `test_isn` and `renege_ppm` controls. Before running a seed, the simulator checks the expected plant, endpoint, traffic, close, MTU and link settings. The profile accepts generated Stack seeds only and rejects overrides for imported scenarios, synthetic nodes, test faults, plants, event limits, reduced checking and shortened captures. Counts belong to this named defensive profile.

## Run on Linux

Build on the assigned cores. Start the campaign from the committed worktree so the plan records the source commit, source tree, simulator binary hash, runner hash, range, options and registered seed-list hash.

```sh
taskset -c 16-21,28-29 nice -n 10 cmake --preset gcc-sweep
taskset -c 16-21,28-29 nice -n 10 cmake --build --preset gcc-sweep --target utcp-sim -j 8
ctest --preset gcc-sweep -R '^sim\.defensive_gen6$' -j 1

taskset -c 16-21,28-29 nice -n 10 python3 -I tools/defensive_gen6.py run \
  --sim build/gcc-sweep/apps/utcp-sim/utcp-sim \
  --out /private/path/to/campaign --cpus 16,17,18,19,20,21,28,29

taskset -c 16-21,28-29 nice -n 10 python3 -I tools/defensive_gen6.py verify \
  --out /private/path/to/campaign
```

Use an empty directory for a new run. Repeat the original command to resume, or use `--phase primary` and `--phase replay` with the same campaign arguments. `--seeds LO:HI` selects a smaller smoke range. Eight pinned workers use at most one worker on each assigned logical CPU. The virtual simulation uses no external interfaces or services.

The campaign registers exactly the seeds divisible by 500 in the half-open range. The full range therefore registers 2,000 seeds from 0 to 999,500. Each received result is retained in the compressed primary shard with a receipt. An interrupted staging directory contributes zero accepted rows. Completed work is validated by range, strict result fields, exact seed order, counts and SHA-256 before reuse. A corrupt or incompatible published receipt causes a verification error. Preserve the original output directory when diagnosing a published failure or running a new binary.

Each eligible registered seed gets one traced replay with full packet captures of ingress and egress at both endpoints. The primary run and replay must match across every deterministic result field, including the canonical configuration SHA-256 and the simulator's rolling digest of transmitted and delivered datagrams, socket events, errors and verdict. Only measured wall time is omitted from equality. Each retained artifact has a separate SHA-256 and byte count. Primary failures retain the original result or process diagnosis. A failed or ineligible registered replay retains its diagnostic receipt and contributes zero matched captures. Any non-OK primary outcome or unmatched registered replay makes the campaign exit nonzero.

For an offline protocol spot check, use TShark to decode a fixed selection of the retained captures in both directions, check successful handshake, application payload and FIN, and inspect malformed-frame and checksum counts. The testbed image already contains TShark. Use the cached image with pull disabled and networking disabled for offline inspection.
